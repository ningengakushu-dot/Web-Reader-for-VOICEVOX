# v1.4.3 release candidate

## Included fixes

- Chromeのエラー一覧に、テキスト未選択という想定内操作を記録しない
- 更新案内のレビューリンクを公開済み拡張機能のレビューページへ修正
- 特定の星数を求めず、率直な評価を依頼する文言へ変更
- v1.4.2以前からv1.4.3へ更新した場合、修正済みの更新案内を一度表示

- ページ内アイコンのサイズ上限を64pxから128pxへ拡張

- 縦書きOCRの精度改善（方向曖昧時の全体並行比較・重複挿入除去・短列漢字の局所再確認）と「ルビ優先読み」設定の削除（[検証記録](OCR-ACCURACY.md)）
- OCR進捗表示を主経路の認識だけで組み立て、開始直後に100%近くで止まって見える問題を修正

### 2026-08-16 公開前監査での修正

- 読み上げ中のタブを閉じても音声が鳴り続けていた問題を修正（停止手段が無くなる）
- 停止（STOP_ALL）のためだけに offscreen ドキュメントを生成しないようにし、タブ遷移時の停止も他の音声操作と直列化
- 古い範囲OCRの結果が、後から始めた読み上げ（選び直し・テキスト選択・停止後）を中断・上書きしないよう要求に通し番号を付けて照合
- VOICEVOX に接続できない・応答が無い失敗では残りの文を合成し続けず、文の数だけエラー通知が飛んでいた問題を修正（HTTPエラーで特定の文だけ拒否された場合は従来どおり次の文へ進む）
- OCR範囲選択オーバーレイを閉じたとき、フォーカスを元の要素へ戻す
- 長い文（120字超）は読点・空白の直後で分割して合成する。合成は「再生中1件＋先読み1件」で進むため、句点の無い長い箇条書き（メールの求人紹介等）が1件になると、その合成（実測: 約390字＝音声55秒の合成に26秒）が直前の文の再生時間に収まらず、文の間に20〜30秒の無音が空いていた。読点単位なら各件の合成が数秒で先読みが追いつく（実機の VOICEVOX で同じ本文を計測し無音ゼロを確認）。読点の無い部分は600字まで切らず、それを超えるときだけ機械的に切る（エンジンの要求サイズ上限・60秒タイムアウト対策）

### 2026-08-16 読み上げパイプラインの設計見直し（多様な入力への対応）

上記の無音は一例に過ぎず、公開後は Web ページ・画像・PDF 由来の多種多様な文章が OCR 経由で読み上げられる。
実エンジン（VOICEVOX 0.25）に文字種・記号・長さ別の文字列を投げて挙動を確認し、Web レイアウト 8 種を実際に OCR した生テキストと
代表・境界・異常系のコーパス 35 件（[tools/reading-corpus.mjs](../tools/reading-corpus.mjs)）で「途切れ・失敗・不自然な読み」を計測したうえで、
場当たりの修正ではなく次のように設計を改めた（計測ツール: [tools/reading-corpus-check.mjs](../tools/reading-corpus-check.mjs)）。

- **すべての経路が通る background 側で整形する**（`sanitizeSpeechText`）: 合成を欠落させる制御文字（U+0000 以降が消える）、無音なのに長い間になる不可視文字（ゼロ幅・BOM・ソフトハイフン・双方向制御・結合文字）を除去。同じ記号の3個以上の連続（罫線・点線リーダー・強調）は1個に。全角英数字は半角に。OCR で「https:/」と崩れた URL・`www.`・「ドメイン/パス」も「URL省略」に。日付 `2026/08/16`→「2026年8月16日」、時刻 `10:30`→「10時30分」、`¥12,800`（OCR の `\12,800` 含む）→「12,800円」、㎡ ㎏ ㈱ 等の合成文字を読みへ（いずれもそのままだとエンジンが「ゼロハチ、ジュウロク」「エン、イチマン…」「無音」と読む）
- **分割の単位を文字数ではなく「読み上げコスト」で決める**: 実測で数字は1桁あたり日本語の3〜4倍、辞書に無い英字列・16進は約2倍の時間がかかる（`123456…`600字は音声4分以上＝合成が60秒のタイムアウトを超えて失敗する）。数字3・英字1.5・その他の文字1で重み付けし、上限120（区切りが無い塊は300）を守る
- **区切りの強い順に分ける**: 。！？改行（閉じ括弧・閉じ引用符は前の文へ）→ 英文の文末・読点（略語 `Mr.`・桁区切り `1,000` では切らない）→ 空白 → 記号の境 → 機械的。分ける必要があるときは端数を余らせず均等に（「…across all major regions」＋「this year.」のような切れ端を作らない）。項目名と値を結ぶコロンでは切らない
- **先頭の数件は小さく**（40→60→90→120）して、クリックから最初の音が出るまでを短くする。節の区切りが無い文や、切り出した先頭が短すぎる場合はやめる（直後の長い件の合成が短い音声の再生中に終わらず、開始直後に途切れる方が目立つ）
- **記号・罫線だけの断片は送らない**（無音の合成要求）。読める文字が無い選択は「読み上げられる文字がありません」を返す。件数上限（5,000）を超える分は読まず、その旨を最後に一言添える（黙って失敗しない）
- **先読みを「次の1件」から「完成済み音声が45秒分・24件まで」へ**（offscreen）: 短い見出し・箇条書きの1行の直後に長い文が来ると、その合成（音声長の0.3〜0.7倍）が短い音声の再生中に終わらず途切れていた。数十秒分の音声がたまっていれば1件の合成時間を吸収できる。24kHz WAV は1分で約2.9MB なのでメモリは文章量に依存しない一定範囲
- **テキスト選択の経路も改行を残す**（content.js）: 見出しと本文が1つの長い「文」につながって分割位置が不自然になっていた
- **OCR テキスト整形**（`normalizeOcrText`）: 英文の折り返し（Tesseract は行間が広いと行の間に空行を出す）を同じ文としてつなぐ、「第N章／第N条」の番号付き行と「価格：…」の項目名＋値の行を1行1項目として間を入れる（目次が「はじめに3第2章導入12…」と切れ目なくつながっていた）。小説コーパス・kakushin・MS の出力（tools/ocr-e2e、23件）は変更前後で完全一致
- **エンジンの制約への対処**: 句読点・空白（＝間）の無いままアクセント句が49を超えると VOICEVOX の audio_query が 500 を返す／以降の読みが欠落する（実測: 句読点の無い和文276字、16進60字、句読点の無い英文60語）。区切りの無い塊は上限（和文120字≒40句）で必ず切り、25字以上の英数字の塊（ハッシュ・base64）は12字ごと、17桁以上の数字列は4桁ごとに空白を入れる（1文字ずつ読む塊では聞こえ方も自然）
- **罫線付きの表の OCR**（`recognizeWithOrientation`）: 横書きで明らかに低品質（confidence < 55）なら PSM=AUTO で再認識する。横書き worker の SINGLE_BLOCK は縦罫線で行分割が破綻し（実測 17）、その壊れた結果より縦書き worker の結果（44）が高いため列を縦に読んだ文字列になっていた。AUTO なら 85（CER 96.9%→6.3%）。小説コーパス・kakushin・MS は同一セッションの A/B で出力バイト一致（[検証記録](OCR-ACCURACY.md)）

実機（VOICEVOX 0.25、CPU）でコーパス 39 件・全チャンクを実際に合成した結果は [RC-1.4.3-TEST.md](RC-1.4.3-TEST.md) の確認項目に反映。合成失敗ゼロ、再生の模擬で文の間の無音ゼロ。

既知の限界（対処せず・記録のみ）: 句読点も空白も無い長文は上限で機械的に切るため語の途中で切れることがある（切らずに送るとエンジンが失敗するため）。OCR の誤認識（数値の桁化け・記号「◆」→「る」の誤読）は整形では直せない。英語の一部の語（We 等）をエンジンが1文字ずつ読む。

### 2026-08-16 明朝体の誤読報告を受けた OCR の改善

- **整列一致による余剰文字の削除段**（`pruneOcrConsensusInsertions`）: 倍率違いの認識結果を文字単位で整列し、採用中の結果にしか無い文字（両隣が対応付いた候補すべてが「その位置に文字なし」で一致し、確信度95未満）を削除する。追加OCRなし。横書きにも効く（従来の重複除去は縦書き専用）。実測（AAあり明朝24枚を新設したコーパス＋既存9入力、HEAD比・逐次）: 誤り 128→123、改善5・悪化0（削除されたのは「ぎ」「は」「人」「和」「ぬ」の余剰挿入のみ）。予算9/12/15/60秒で出力一致、再実行で一致、待ち時間は変化なし
- 測定基盤: `tools/ocr-e2e` の入力取り込みを実機と同じ画素完全に修正（等倍で再標本化していた。旧数値は約15%甘い）、AAあり明朝コーパス（游明朝・BIZ UD明朝・Noto Serif JP、16〜24px、DSF 1/1.5、縦横・暗背景）を追加
- 実測して不採用: 文字数膨張ゲート（1入力で悪化）、AA入力で二値化を省く分岐（精度上の利得ゼロ）、PDF テキスト層の直読み（file:// と選択範囲の特定が塞がっている）、ズーム再キャプチャ（実機のみ・副作用大）。詳細は [OCR-ACCURACY.md](OCR-ACCURACY.md) の 2026-08-16 節
- エラートーストの自動消去が、直後に始めたOCRの進捗表示と見張りタイマーを巻き添えで消していた問題を修正
- 読み上げ依頼の失敗理由（テキストが長すぎる等）をトーストで表示
- 自前UI（アイコン・OCRオーバーレイ・更新案内）のホスト要素がページのレイアウト（flex/grid の gap 等）に影響しないよう 0×0 の固定配置に変更
- 更新案内カードが範囲読み上げの対象・キャプチャに写り込まないよう、範囲選択中〜OCR終了まで一時的に隠す
- bfcache から戻ったページで「読み上げ中」表示が固着し最初のクリックが空振りする問題を修正
- OCR範囲選択オーバーレイにフォーカスを移し、iframe にフォーカスがあっても Esc でキャンセルできるように
- ページ内アイコンに role/aria-label/title を付与（既定の円でもホバーで説明が出る）。トースト・アイコンの z-index を最前面に統一
- OCR: 精錬段の失敗で主経路の認識結果まで捨てて全体を失敗させない／行bboxが無い結果でも落ちない／整列表のセル数上限（極端な文字数での数十MB確保を回避）／worker生成の後始末（出力は9入力で変更前後完全一致を実測）
- capture.html の受信メッセージに送信元検証を追加。file:// をキャプチャできない場合の案内文を追加。ツールバーのエラーバッジを該当タブに限定
- 設定画面に VOICEVOX 公式サイトへのリンクとショートカットの案内を追加。設定読込失敗時の表示を追加
- CI: 未登録だったテスト2件と新規テスト2件を登録、upload-artifact をSHA固定、RC zip 名を manifest から取得
