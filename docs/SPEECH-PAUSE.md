# 音声合成待ちを抑える再生制御

## 原因と対象

句読点そのものが原因ではない。合成単位の境界で、完成済み音声を使い切る前に次の音声が
完成しないと無音になる。句点・改行・見出し・箇条書き・英文・長文の機械分割で共通する。
特に開始直後や、短文が複数続いてから長文になる箇所では、先読みの上限が24件・45秒あっても、
必要量が蓄積する前に再生を始めることで不足する。

この修正は合成待ちを対象とする。VOICEVOXが音声自体に含める句読点・括弧等の休止は別の要因であり、
この変更では音声内容や休止設定を変更しない。

## 再生側での対策

1. 既存の文章整形・分割はそのまま使う。短文の結合や改行の削除は行わない。
2. 完成済み音声と合わせて24件・45秒の範囲で、先の複数のaudio_queryを取得する。
   波形を作る前に、エンジンが返すモーラ長と話速・休止設定から各音声の長さを見積もる。
3. 各合成の所要時間を実測し、直近の「合成秒数÷音声秒数」に20%の余裕を加えて更新する。
4. 先の複数単位について、累積の合成時間から、その前までに再生できる音声時間を引く。
   この不足の最大値に0.1秒の余裕を加え、開始時に確保する音声量を決める。
   次の1件だけが短くても、その後の長い合成を見落とさない。
5. 必要量に満たない場合は再生開始を待つ。合成完了時と、進行中の合成の残り時間が十分短くなる時点で
   再評価する。先頭が十分長ければ後続の全合成を待たない。
6. 再生が続いている間は、完成した次の音声を即座に再生する。予測の更新を理由に間を追加しない。
   実際にバッファが空になった場合だけ、再開に必要な量を再確保する。

先読み済みのクエリは合成時に再利用する。失敗は元のキュー順で処理し、HTTPエラー時の分割再試行、
到達不能時の打ち切り、停止時の世代破棄を維持する。停止時には開始待ちタイマーも解除する。
音声メモリの上限と開始待ちが互いに待ち合わないよう、上限に達した場合は再生を開始する。

## 実エンジンでの確認（2026-10-24）

VOICEVOX Engine 0.25.2、話者3、話速1、標準の休止設定。実際のaudio_query・合成の所要時間と
WAVの長さを採取し、同じデータを変更前（b71687c）と変更後の出荷用entry/audioへ渡した。
再生開始・終了・タイマー・先読みは仮想時計で動かした実装そのものを使い、予測式の別実装にはしない。
Chromeの実際の音声出力イベントや聴感から測った値ではない。

| 例 | 途中の最大合成待ち：前→後 | 開始待ち：前→後 |
|---|---:|---:|
| 添付例「正しい。」＋本文 | 1.709→0秒 | 0.376→3.029秒 |
| 改行した「概要」＋本文 | 1.798→0秒 | 0.416→3.074秒 |
| 「はい。正しい。」＋本文 | 1.398→0秒 | 0.320→3.238秒 |
| 句読点のない長文 | 0→0秒 | 3.750→3.779秒 |
| 改行された短文の列 | 0→0秒 | 0.316→0.346秒 |
| 英文の段落 | 0→0秒 | 1.033→1.215秒 |

浮動小数点の誤差は0秒として記載。6例・30単位の音声合成が成功し、全文を順序どおり再生して終了した。
開始前に必要な音声を蓄えるため、特に短い見出しから始まる場合は開始待ちが増える。
話速2・休止倍率2・休止長指定についても、見積もりと実WAVの長さの差が約0.002～0.007秒であることを確認した。

## 検証範囲と限界

一定の合成速度での短文→長文、短文→短文→長文を、句点・改行・箇条書き・英文・記号なしの各ケースで
検証する。話速2、長い先頭、単一文、上限を超える負荷、待機中・クエリ取得中の停止と再開も回帰検査に含める。
本文の整形と分割は変更前と同じなので、テキストの結合によって読みを変える対策ではない。

合成速度は予測値であり、途中の急なCPU負荷増大・エンジン停止・取得失敗まで無音ゼロを保証するものではない。
長時間、音声の生成が再生より遅い環境では、有限のバッファだけで途切れをなくすことはできない。
利用中の拡張機能への反映と、実際のキャプチャ画面での再生確認は別途必要。

再測定は出力先のaudioディレクトリを作成し、同じエンジンを使う他の計測を止めて実行する。

```powershell
node tools/reading-corpus-check.mjs --only capture_short_answer,capture_heading,capture_short_run,long_no_punct,english_paragraph,short_lines --json audio/adaptive-buffering.json
```

JSONのbeforeとnowは、同じ音声・API所要時間を使う出荷コードの比較結果。
--baseline-refで比較元のbackgroundとentry/audioを指定できる。既定の比較元はb71687c。
