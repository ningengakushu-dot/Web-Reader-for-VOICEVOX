# 短文の句点後に生じる合成待ちの修正

## 原因

「正しい。」のような短文も必ず別の合成要求にしていたため、先頭の約0.9秒の音声が
終わるまでに後続の長文を合成できなかった。先読み上限は24件・45秒あるが、読み始めには
まだ蓄積がなく、上限を増やしても解消しない。最初の短文が先頭用の分割目標を1件消費し、
次の文では短すぎる節を切り出さない規則も働いて、長文が丸ごと次の要求になっていた。

## 修正

同じ段落で読み上げコストが20未満の文は後続とまとめ、既存の40・60・90の先頭目標と
120のコスト上限で分割する。20は先頭目標40の半分で、既存の短すぎる節を避ける基準と
そろえた。句点・閉じ括弧・本文は残し、句点の自然な休止はVOICEVOXに処理させる。
短文が連続しても十分な長さになれば結合を止め、文字数・件数の上限も維持する。
改行は段落・見出し・表の境界なので結合しない。OCRの認識処理や先読み上限は変更しない。

## 実エンジンでの確認（2026-10-24）

VOICEVOX Engine 0.25.2、話者3、話速1、標準の休止設定。
添付例の「正しい。」から始まる160文字を `capture_short_answer` に追加した。
比較元は `b71687c`（develop）。報告時の作業ブランチ `11921a4` も同じ分割を返す。

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| 先頭の合成単位のコスト | 3 | 25 |
| 再生開始までの時間 | 0.491秒 | 1.619秒 |
| 途中の合成待ちの最大値 | 1.929秒 | 0秒 |
| 音声合計 | 28.9秒 | 28.9秒 |
| 合成単位数 | 3 | 3 |

途中の待ち時間は、実際に合成した各音声の長さとAPI所要時間を既存の直列合成・先読み・
連続再生モデルに入力した値。Chromeの実際の再生イベントや聴感から測った値ではない。
句点そのものの休止を0秒にしたという意味ではない。初回の別計測では後続合成6.85秒、
先頭音声0.896秒から約5.96秒の待ちも再現しており、機器負荷で所要時間は変動する。

40例の既存・追加コーパスで全件のクエリ取得が成功した。変更前後で本文の文字列
（空白を除く）と読み仮名（アクセント・休止・無声化の記号を除く）が一致した。
ニュース・求人メール・会話文・改行された短文は実音声の合成も確認した。
改行された短文には引き続き機器負荷による待ちがあり、任意の文章・話速・負荷で
途切れがなくなる保証ではない。利用中の拡張機能への反映と実際のキャプチャ画面での
再生確認は別途必要。

再測定は、出力先の `audio` ディレクトリを作成してから以下を順に実行する。
同じエンジンを使う別のベンチマークを同時に動かさない。

```powershell
node tools/reading-corpus-check.mjs --only capture_short_answer --baseline-ref b71687c --json audio/sentence-gap-before.json
node tools/reading-corpus-check.mjs --only capture_short_answer --json audio/sentence-gap-after.json
```

`--baseline-ref` は整形・分割に用いるbackgroundのソースを切り替える。
合成条件とコーパスは実行中の作業ツリーのものを使う。
