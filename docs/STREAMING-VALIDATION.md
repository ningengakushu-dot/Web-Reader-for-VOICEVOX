# ストリーミング導入の実機検証

## 現状
- [PR #39](https://github.com/ningengakushu-dot/Web-Reader-for-VOICEVOX/pull/39) は `develop` 向けの Draft。実機検証に使用したコードは `ba47778`（拡張機能 1.4.4）。Chrome ウェブストアの公開版は [1.2.1](https://chromewebstore.google.com/detail/web-reader-for-voicevox/ilcfondcjhaalpcghnhcejioopcbhhla)。
- OCR 結果タブの再読み込みで音が残る問題は、Chrome の回帰試験と Surface Pro 7 の音声出力測定で修正を確認した。通常合成の長文とストリーミングの短文を実際に聞く確認が残っている。提出前の確認は [ストア提出手順](STORE-SUBMISSION-1.4.4.md) を参照。
- **既存利用者・未設定ユーザーの既定値は通常合成。ストリーミングは設定画面で明示的に選んだ場合だけ有効。**
- ストリーミングを選んだ場合も、単一の読み上げ単位に限って、ENGINEの機能フラグと `streaming_talk` スタイルを確かめてから使用する。
- **複数文の読み上げは、文間の無音を増やさないため、既存の通常合成へ明示的に退避している。** これは品質上の暫定制限であり、全文章への自動ストリーミング対応が完成したわけではない。
- **再生を始める前にストリーム全体を検証する。** 5秒を超える音声、途中切断、欠損、サイズ不整合はPCMを出力せず、解放後に通常合成へ退避する。PCMは長さを検証したAudioBufferに直接格納し、全量検証後に1回で予約する。5秒超による切り替えはその要求だけに適用する。クエリの推定長が5.5秒を超える場合は、同じクエリで通常合成を直接実行する。35秒の受信停止から復帰した場合も、再生は全PCMを受信した後に始まる。
- 再生予約後に失敗した場合は、音源停止を先に要求し、レンダリング側のAnalyserNodeと音声クロックで先頭PCMの出力がない場合だけ、`AudioContext.close()`完了後に通常合成へ退避する。出力済み・出力確認不能・取消し失敗では重複再生を避け、通常合成へ戻さない。Chromium実クロックを独立して進めるブラウザ回帰テストで、同期`abort()`遅延中の開始境界を確認する。
- 同一Offscreenで停止→即再生を行う場合は、先行AudioContext.close()が完了するまで次のプレイヤー開始を待つ。通常合成中の停止は再生をすぐ取り消し、次のクエリや合成は旧通信の完了または既存タイムアウトを待つ。標準の `/synthesis` は通信を切っても ENGINE 内で演算を続けるため。短時間に再開を繰り返しても、待機中に取り消された要求は ENGINE へ送らない。
- reader.cancel()は最大1.2秒、AudioContext.close()は最大3秒を並列に待機し、無期限待機を回避。abortに伴うAbortErrorまたは既に失敗したreader.read()と同一理由によるcancel拒否は、AudioContext解放・予約音源停止が確認できた場合に限り正常な後始末として扱う。cancel未解決・予期しない拒否、close失敗・タイムアウト、予約音源停止失敗はSTOP_AUDIO失敗とし新規再生を禁止する。Promise拒否値がundefined/nullでも安全ロックが確実に設定される。終了失敗時の復旧には拡張機能の再読み込みが必要。Fetch相当の異常系・同一Offscreenで50回連続停止再開のモック検証を追加（実機検証は未実施）。
- 無通信20秒で即座に中断せず、同じストリーム読み込みに追加40秒の猶予を設ける。最大60秒・受信から最終再生まで単調時計による10分の有限上限。音声クロック停止中でも最終再生待ちが期限を超えたら停止・解放・エラー通知まで進む。
- VOICEVOX 0.26.0公式実装のストリームは44-byte固定ヘッダー＋16bit PCMである。

## 2026-11-14 追加実機検証

- Windows、Ryzen 5 3600（6コア・12論理プロセッサー）、公式 VOICEVOX ENGINE 0.26.0 Windows CPU 版、隔離プロファイルの画面表示あり Chrome for Testing 119.0.6045.105。公式アーカイブの SHA-256 を確認し、既存の 0.25.2 と別ポートで起動した。拡張機能の通常の接続先からローカルの転送プロキシを経由し、合成は実 ENGINE が担当した。話者は四国めたん ノーマル（style 2、`streaming_talk`）。
- 短文「こんにちは。」はストリーミング HTTP 200 で完走。長い1文はストリームの後に通常合成が1回発行されて完走した。実 ENGINE を WAV 先頭の受信後に強制終了すると、フォールバック先も接続できず OCR 結果画面に再生エラーが出た。ENGINE を再起動し、同じ画面から再生を再試行して完走した（強制終了試験は Chromium 156）。
- 50回の連続停止では、実 ENGINE の WAV 先頭44 byteを転送したところで応答を保留し、停止してすぐ同じ短文を再開した。50個の異なる要求 ID が各1回ずつ準備・停止中・停止完了を通知し、追加合成や詰まりは発生しなかった。全回で停止完了までにクライアント側通信が閉じ、試験終了後に通常の受信へ戻すと再生できた。全体9.74秒。1・10・20・30・40・50回目はキュー0、プレイヤーなし、後始末完了を確認した。ENGINE 内の演算が各停止で即座に中断されるかは未測定。
- 模擬 HTTP を使った Chromium 156 の実時間試験では、35秒の無通信後に再開し36.12秒で完走（通常合成0回）。応答を返さない場合は60秒で切断し、通常合成1回を経て61.20秒で完走した。時間上限は短縮していない。
- Offscreen を受信中に破棄すると、修正前は準備中の表示が残った。修正後は通信の終了、理由表示、次の要求での Offscreen 再作成を確認した。停止応答待ち中の Offscreen 破棄は停止完了になった。Service Worker を停止・再起動すると再生中の要求 ID が復元され、同じ要求を停止できた。2タブ同時開始、別タブからの停止、停止応答保留中の高速ショートカットと iframe 削除も確認した。
- Chrome 119 の再読み込みで旧メイン文書の `pagehide` が届かず、通信が残るケースを確認した。新メイン文書の初期化時にも文書 ID を照合し、旧文書の要求を止めるよう修正した。`pagehide` の通知を無効化した回帰で確認した。
- 画面表示ありの Chrome for Testing 119.0.6045.105 とインストール済み Google Chrome 157.0.8103.52 で、隔離プロファイルに拡張を読み込み、両方で同じ回帰が成功した。既存利用プロファイルの設定・他の拡張との組み合わせは手動確認に残す。
- インストール済み Chrome 157 の隔離プロファイルと実 ENGINE 0.26.0 でも確認した。短文の「再生中」表示後に停止し、その要求に終了通知が出ず停止通知が1回届いた。直後に再開して完走した。ストリーミングは計2回、通常合成は0回。
- MV3 境界は同じ拡張 ID に加え、送信者の URL とタブの有無、ページ離脱ではトップフレームと文書 ID で判定する。再生状態取得は外部向けに公開していない。別オリジン iframe からの合成キーイベントでは音声状態が変わらず、停止失敗の HTML 風文字列は画面に文字のまま表示された。OCR 結果は textarea の値、出典・エラーは `textContent`。権限・CSP に変更はなく、ブラウザ回帰中の CSP 警告と未処理のページ例外は0件。

## 合否基準を測定前に設定する
| 分類 | 合格基準 | 確認方法 |
| --- | --- | --- |
| 後方互換性 | ENGINE 0.25.2、非対応スタイル、判定失敗でも通常合成で完走 | Windows + 実ENGINE |
| 音声完全性 | 再生開始・停止を除いて読み飛ばし/重複なし。途中の意図しない無音・明瞭なクリックノイズなし | PCM固定波形の照合 + 聴感 + 録音波形 |
| 再生イベント | `PLAYBACK_ENDED` は最後のサンプルの後に1回のみ。停止後は古い音声が鳴らない | 計測ログ + Chrome Offscreen実機 |
| リソース | 10回連続再生後も未再生バッファが累積しない。停止でAudioContext・通信を解放 | Chromeタスクマネージャー + プロファイラ |
| 性能 | 同じENGINE・話者・文章・設定・環境で通常合成と比較し、改善を実測できた項目のみ報告 | 5回以上測定、中央値と遅いケースを記録 |
| 安定性 | 再生が不安定なら「通常合成のみ」へ戻せる。ENGINE停止中でも合成方式を保存できる | 設定画面で保存→再読み上げ |

速度・メモリ削減の数値目標を恣意的に設定しない。音声品質や安定性に劣化が認められたら不合格とする。

## 実機確認の手順（手動）
1. Chrome 119以上とVOICEVOX ENGINE 0.25.2 / 0.26.0を用意する。話者スタイルの`type`とENGINEの`/version`を記録する。VOICEVOXアプリ本体のバージョンではなくENGINEのバージョンを記録。
2. 短文（1文）、長文、句読点の多い複数文、10回の連続読み上げを用意する。非対応スタイルと`streaming_talk`を区別する。
3. 既定の通常合成のままで読み上げた場合と、対応環境でストリーミングを明示的に選んだ場合を順に実施。話速・ピッチ・抑揚・音量・間を同じ値に固定。
4. 先頭・中間・末尾の音、停止/再開、ENGINE停止・再起動、タブ切替、複数タブ、Service Worker再起動、Offscreen再生成を確認。再生予約後〜出力直前のエラー、音声クロックが出力時刻をまたぐ瞬間のエラー、通信20秒超の一時停止と60秒超の断絶、停止直後の新規再生も検証する。
5. ENGINEとChrome拡張機能のメモリを別々に記録する。ENGINE起動後の基準値・再生中ピーク・停止後・10回終了後、CPU使用率、再生開始までの時間、音切れ発生回数を記録する。
6. このPCの検証を終えてから、仕上げとして低性能PCで同じ文章の長文・連続再生を確認する。
7. `check`、`architecture-contract`、`CodeQL`、`build-release-candidate`すべて成功、実機検証と数値報告が揃ってから完成判定する。

停止境界の実ブラウザ回帰は、`tools/ocr-e2e`のPlaywright依存がある環境で次を実行する。

```powershell
$env:OCR_CHROMIUM = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
node tools/test-streaming-race-browser.mjs
```

Offscreen 初期化待ちと WAV 受信待ちの停止は、拡張機能を読み込める Playwright 版 Chromium で `node tools/test-streaming-stop-browser.mjs` を実行して確認できる。初期化待ちの停止、iframe の追加と遷移、停止失敗と再試行、タブ切替・再読み込み、通常合成へのフォールバックを模擬 ENGINE で検証する。別の対応 Chromium を使う場合は `OCR_CHROMIUM` に実行ファイルを指定する。

Chrome 119 は `OCR_HEADED=1` を設定して画面表示ありで実行する。インストール済み Chrome で DevTools 経由の拡張読み込みを使う場合は、隔離プロファイルの検証に限り `OCR_LOAD_VIA_CDP=1` を指定する。35秒および60秒の実時間試験は `node tools/test-streaming-stop-browser.mjs network-stall` で実行する。

### OCR 結果読み上げの負荷対策

- 報告画像に近い88文字を結果欄へ入力し、Chrome 157 と実 ENGINE で測定した。3チャンク（14・44・30文字）が通常合成され、ENGINE 0.25.2 の約1秒窓の CPU ピークは48–49%、0.26.0 は49–54%だった。最後の WAV 受信後に負荷が下がり、読み上げ完了後の約2秒はほぼ0%だった。
- 同じ Offscreen が先行の通常合成を追跡している間に停止・即再開すると、同時 HTTP 合成数は模擬 ENGINE で修正前2件、修正後1件。応答または既存の通信タイムアウトまでは再開側が準備表示になり、その間に取り消した要求は送られない。Offscreen が破棄された場合やストリーミング停止直後に通常合成を始める場合は、この待機の対象外。独立レビューの模擬 ENGINE では、いずれも旧処理が残っている間に次の要求が届いた。計測対象は HTTP 要求数であり、ENGINE 内の演算終了時点は未測定。
- ストリーミングは全量を検証してから再生するため、`segment_length` を0.3秒から5秒へ変更した。バッファに収まる音声はまとめて生成する。実 ENGINE 0.26.0 の API を各5回測定したところ、全量受信の中央値は約0.94秒の音声で522→293 ms、約2.94秒の音声で1433→776 ms。取得した変更後の PCM は、各例とも同じクエリの通常合成とサンプル単位で一致した。
