# ストリーミング導入の実機検証・公開ゲート（未完了）

## 現状
- PR #39 の修正対象は、GitHub から取得した `fac6fdf3212a83abb86ea80c65f183e211b29069`。対象は `develop`。
- **既存利用者・未設定ユーザーの既定値は通常合成。ストリーミングは設定画面で明示的に選んだ場合だけ有効。**
- ストリーミングを選んだ場合も、単一の読み上げ単位に限って、ENGINEの機能フラグと `streaming_talk` スタイルを確かめてから使用する。
- **複数文の読み上げは、文間の無音を増やさないため、既存の通常合成へ明示的に退避している。** これは品質上の暫定制限であり、全文章への自動ストリーミング対応が完成したわけではない。
- **再生を始める前にストリーム全体を検証する。** 5秒を超える音声、途中切断、欠損、サイズ不整合はPCMを出力せず、解放後に通常合成へ退避する。PCMは長さを検証したAudioBufferに直接格納し、全量検証後に1回で予約する。5秒超による切り替えはその要求だけに適用する。35秒相当の遅延は全PCM受信後に再生を始め、開始時間が延びる。実機の音質・開始時間は未測定。
- 再生予約後に失敗した場合は、音源停止を先に要求し、レンダリング側のAnalyserNodeと音声クロックで先頭PCMの出力がない場合だけ、`AudioContext.close()`完了後に通常合成へ退避する。出力済み・出力確認不能・取消し失敗では重複再生を避け、通常合成へ戻さない。Chromium実クロックを独立して進めるブラウザ回帰テストで、同期`abort()`遅延中の開始境界を確認する。
- 同一Offscreenで停止→即再生を行う場合は、先行AudioContext.close()が完了するまで次のプレイヤー開始を待つ。STOP_AUDIOは後始末の完了後にのみ成功応答を返し、停止中のENQUEUE_TEXTSは通常合成も含めて待機させる。
- reader.cancel()は最大1.2秒、AudioContext.close()は最大3秒を並列に待機し、無期限待機を回避。abortに伴うAbortErrorまたは既に失敗したreader.read()と同一理由によるcancel拒否は、AudioContext解放・予約音源停止が確認できた場合に限り正常な後始末として扱う。cancel未解決・予期しない拒否、close失敗・タイムアウト、予約音源停止失敗はSTOP_AUDIO失敗とし新規再生を禁止する。Promise拒否値がundefined/nullでも安全ロックが確実に設定される。終了失敗時の復旧には拡張機能の再読み込みが必要。Fetch相当の異常系・同一Offscreenで50回連続停止再開のモック検証を追加（実機検証は未実施）。
- 無通信20秒で即座に中断せず、同じストリーム読み込みに追加40秒の猶予を設ける。最大60秒・受信から最終再生まで単調時計による10分の有限上限。音声クロック停止中でも最終再生待ちが期限を超えたら停止・解放・エラー通知まで進む。
- VOICEVOX 0.26.0公式実装のストリームは44-byte固定ヘッダー＋16bit PCMである。
- 本PRの設計・CIテストだけでは、Chrome Offscreen Documentの実音とCPU・メモリ改善は証明できない。

## 2026-11-14 独立レビュー対応

- 通常合成の先読み、再生、停止と停止待ちの応答で、`null`／`undefined` の拒否をテスト。再生エラーの通知は1回で、再生状態とBlob URLを解放する。
- PCMが0サンプルのWAVは再生前に拒否。AudioContextを生成せず、通常合成への1回の切替で開始・完了を通知する結合回帰テストを追加。
- 音声要求をOffscreenに渡す前に、要求元タブの全フレームへ準備中を通知する。模擬ENGINEが部分WAVを送って待機する間に、Chromiumの実拡張でアイコンとAlt+Shift+Uから停止し、通信が閉じて合成が再発行されないことを確認した。
- 再レビューの指摘を受け、Chromiumで最初の再生予約直後に320 msの処理遅延を注入し、全PCMが1回で予約されることを確認するテストを追加。同じ話者で6秒の音声が通常合成へ切り替わった直後に、短文のストリーミングが完走することも結合テストで確認する。

## 合否基準を測定前に設定する
| 分類 | 合格基準 | 確認方法 |
| --- | --- | --- |
| 後方互換性 | ENGINE 0.25.2、非対応スタイル、判定失敗でも通常合成で完走 | Windows + 実ENGINE |
| 音声完全性 | 再生開始・停止を除いて読み飛ばし/重複なし。途中の意図しない無音・明瞭なクリックノイズなし | PCM固定波形の照合 + 聴感 + 録音波形 |
| 再生イベント | `PLAYBACK_ENDED` は最後のサンプルの後に1回のみ。停止後は古い音声が鳴らない | 計測ログ + Chrome Offscreen実機 |
| リソース | 10回連続再生後も未再生バッファが累積しない。停止でAudioContext・通信を解放 | Chromeタスクマネージャー + プロファイラ |
| 性能 | 同じENGINE・話者・文章・設定・環境で通常合成と比較し、改善を実測できた項目のみ報告 | 5回以上測定、中央値と遅いケースを記録 |
| 安定性 | 再生が不安定なら「通常合成のみ」へ戻せる。ENGINE停止中でも合成方式を保存できる | 設定画面で保存→再読み上げ |

速度・メモリ削減の数値目標を恣意的に設定しない。音声品質や安定性に劣化が認められたら不合格とする。

## 実機確認の手順（手動）
1. Chrome 119以上とVOICEVOX ENGINE 0.25.2 / 0.26.0を用意する。話者スタイルの`type`とENGINEの`/version`を記録する。VOICEVOXアプリ本体のバージョンではなくENGINEのバージョンを記録。
2. 短文（1文）、長文、句読点の多い複数文、10回の連続読み上げを用意する。非対応スタイルと`streaming_talk`を区別する。
3. 既定の通常合成のままで読み上げた場合と、対応環境でストリーミングを明示的に選んだ場合を順に実施。話速・ピッチ・抑揚・音量・間を同じ値に固定。
4. 先頭・中間・末尾の音、停止/再開、ENGINE停止・再起動、タブ切替、複数タブ、Service Worker再起動、Offscreen再生成を確認。再生予約後〜出力直前のエラー、音声クロックが出力時刻をまたぐ瞬間のエラー、通信20秒超の一時停止と60秒超の断絶、停止直後の新規再生も検証する。
5. ENGINEとChrome拡張機能のメモリを別々に記録する。ENGINE起動後の基準値・再生中ピーク・停止後・10回終了後、CPU使用率、再生開始までの時間、音切れ発生回数を記録する。
6. 低性能PCでの長文・連続再生、0.3秒以外の`segment_length`比較は、実装が比較条件を満たすようになってから測定する。
7. `check`、`architecture-contract`、`CodeQL`、`build-release-candidate`すべて成功、実機検証と数値報告が揃ってから完成判定する。

停止境界の実ブラウザ回帰は、`tools/ocr-e2e`のPlaywright依存がある環境で次を実行する。

```powershell
$env:OCR_CHROMIUM = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
node tools/test-streaming-race-browser.mjs
```

受信待ちの停止は、拡張機能を読み込めるPlaywright版Chromiumを使って `node tools/test-streaming-stop-browser.mjs` で確認できる。別の対応Chromiumを使う場合は `OCR_CHROMIUM` に実行ファイルを指定する。
