# Windows 版 初版の配布物検証（2026-11-25）

Windows 11 Pro x64、AMD Ryzen 5 3600、VOICEVOX Engine 0.25.2。話者はずんだもん・ノーマル（スタイル 3）、話速 1.0、音量 100%。Electron 45.5.0 を同梱した Windows 版 0.1.0 の ZIP を展開し、開発サーバーを使わずに EXE を起動した。引数なしの通常起動でも「VOICEVOX リーダー」ウィンドウが開き、閉じてプロセスが終了した。

## 実エンジンと配布画面での計測

本文欄に入力し、Ctrl+Enter の Enter キーイベントから最初の HTMLAudioElement の `playing` イベントまでを計測した。「途中の合成待ち」は、前の音声の `ended` 時に次の音声がなく、再生の再開に必要な蓄積を待った時間の合計。「再生イベントの間隔」は、前の `ended` から次の `playing` までの実測で、メディア要素の切り替え時間も含む。各入力について同一走行での値をミリ秒に丸めて記録した。

| 入力 | 単位数 | 最初の再生まで | 途中の合成待ち | 再生イベントの間隔（順に） |
|---|---:|---:|---:|---|
| 「こんにちは。」 | 1 | 477 ms | 対象なし | 対象なし |
| 「朝の便り」「窓を開けました。」「公園の桜が咲いています。」を改行で連結 | 3 | 480 ms | 0 ms | 16、13 ms |
| 「朝の川沿いの道を歩きながら鳥の声を聞きました」を区切らず 7 回反復 | 2 | 3,124 ms | 0 ms | 15 ms |
| 「概要」の後で改行し、上記の長文を追加 | 3 | 3,544 ms | 0 ms | 20、16 ms |
| 長文の合成中に停止し、直後に「こちらは次の文章です。」を開始 | 1 | 3,707 ms | 対象なし | 対象なし |

各本文について、配布画面の分割結果・エンジンが受け取る合成単位・各単位の再生開始と終了の順序を突き合わせ、重複・欠落がないことを確認した。短い見出しの後に長い合成が続く条件では、初回再生の前に待ち時間が発生した。今回の複数単位の入力では再生途中の合成待ちは観測されなかった。エンジン内部の休止やスピーカーから実際に聞こえる時間は計測対象外。

## 停止・復旧・配布範囲

- 実エンジンへの `/synthesis` 要求開始後、準備中に Esc で停止し、別文章を開始できた。再生中の Esc と再生中のウィンドウ終了も確認した。停止の効力はリーダー側での通信中断と再生・表示の破棄までで、別プロセスのエンジン内部が直ちに空くことは前提にしない。
- テスト専用の空きポートに接続して実際の接続拒否を発生させ、未起動の案内を確認した。そのポートに同じ VOICEVOX の別プロセスを起動し、同じ画面の「再接続」で本文を保持して再生できた。通常の計測先は `127.0.0.1:50021`。既存エンジンに終了・再起動操作は行っていない。
- 話者・スタイルを切り替え、話速 1.25、音量 65% へ変更し、再生中に終了した。再起動後の画面で全項目の復元と本文欄が空であることを確認した。
- 停止後に旧要求の成功・失敗・再生イベントを意図的に遅着させる単体テスト、先読み上限、音声 URL の解放、合成失敗後の再開を検査した。拡張の文章整形・バッファリング・先読み・再生・キュー・合成失敗回帰、JavaScript 構文検査、静的セキュリティ監査も実行した。
- Chrome 配布 ZIP は従来の `tools/pack.ps1` で生成し、全 51 エントリに Windows 用ファイルがないことを確認した。Windows 版のビルドと再現手順は [Windows 版 README](../desktop/README.md) を参照。

## 手元での聴感確認

Windows の普段使う出力デバイスで、表の「概要」＋長文を読み上げ、見出しから本文への間と境界の音切れを聴く。続いて再生中に Esc を押し、別の短文を Ctrl+Enter で開始して、前の音声が混ざらないことを聴く。自動確認したのは再生イベントと状態遷移までで、実際の聞こえ方は未確認。
