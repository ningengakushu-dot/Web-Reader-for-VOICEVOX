# Windows 版の配布物検証

## 0.1.1 の実機結果（2026-11-26）

Windows 11 Pro 24H2 x64、Ryzen 5 3600、VOICEVOX Engine 0.25.2、ずんだもん・ノーマル（スタイル 3）、話速 1.0、音量 100%、高さ 0、抑揚・間の長さ 1.0。両版とも同じ PC で ZIP を展開し、配布 EXE の本文欄に同じ試験文を入力した。開発サーバーは使用していない。

| 本文 | 単位数 | 初回再生まで 0.1.0 → 0.1.1 | 途中の合成待ち 0.1.0 → 0.1.1 | 0.1.1 の再生イベント間隔 |
|---|---:|---:|---:|---|
| こんにちは。 | 1 | 492 → 454 ms | 境界なし | 境界なし |
| 「朝の便り」「窓を開けました。」「公園の桜が咲いています。」を改行で連結 | 3 | 444 → 553 ms | 0 → 0 ms | 18、13 ms |
| 「朝の川沿いの道を歩きながら鳥の声を聞きました」を区切らず7回反復 | 2 | 3,280 → 3,315 ms | 0 → 0 ms | 17 ms |
| 「概要」の後で改行し、上記の長文を追加 | 3 | 3,525 → 4,033 ms | 0 → 0 ms | 21、19 ms |

Ctrl+Enter の Enter から最初の `playing` までを測定した。途中の合成待ちは前の音声終了時に次の音声が不足した時間で、音声切替や波形に含まれる休止は別に扱う。同一条件で各1走。見出し＋長文では開始が508 ms遅く、途中の待ちは両版とも0 msだった。

### 拡張版との対応と改善

| 優先度 | 初版で見つかった差・設計上の課題 | 0.1.1 の対応と検証 |
|---|---|---|
| 高 | 先読み時の合成失敗で、先行する文の音声まで中断する | HTTP 5xx の文を最大3段階まで分割。回復不能のときは先行音声を再生し切って失敗位置を表示する。HTTP応答・再生順・遅延応答・停止競合を固定したテストで検証した。 |
| 高 | 合成が予測より遅れた分を未開始の文からも差し引き、開始時に必要な先読み量を過小評価する | 経過時間を合成中の1件にだけ適用した。短い2文目の後に長い3文目が続く条件を仮想時計で再現し、上表の実測で途中の待ちを確認した。 |
| 高 | 音量の上限と声の調整項目が拡張版と異なる。括弧の前後に余分な間が入り得る | 音量0～200%、声の高さ・抑揚・間の長さに対応。実際の合成要求、設定変更後の再起動、旧設定の読み込みを検証。括弧を含む4例と通常文1例で実エンジンの選択したアクセント句が拡張版と一致した。 |
| 中 | キーボード操作中にボタンが無効化されるとフォーカスを失い、進捗の通知が音声に重なる | 操作の可否とフォーカスを別に管理し、支援技術への通知は準備・初回再生・終了時に送る。配布画面でTab往復、Ctrl+Enter、Esc、非表示の無効入力への誘導、IME変換イベント中のショートカット抑止と通知順を検証した。 |
| 中 | Windowsの右クリック貼り付け、文字の拡大操作がない | ネイティブ編集メニューと「表示」メニューを追加。実際の右クリックで貼り付け項目が開くことと、200%表示で横方向にはみ出さないことを確認した。 |

操作設計では、入力位置が追えること、キーボードで目的の項目まで移動できること、本文への貼り付けをWindowsの既定操作で行えることを基準にした。[Microsoftのキーボード操作ガイド](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-interactions)・[Electronのネイティブコンテキストメニュー](https://www.electronjs.org/docs/latest/tutorial/context-menu)

### 配布時の受け入れ確認

- 各本文で、`origin/develop` の分割結果、配布画面の分割結果、エンジンへの要求、各単位の再生開始・終了が順番どおり一致した。Windows版は拡張の事前クエリ取得を使わず、実測速度と読み上げコストで先読み量を決める。
- エンジン未起動を専用ポートで再現し、本物のエンジンをそのポートに起動した。同じウィンドウの「再接続」で編集中の本文を読み上げられた。既存エンジンは通常どおり稼働を続けた。
- 長文の合成応答をドライバーで保留し、停止後に「こちらは次の文章です。」を開始してから旧応答を返した。元の要求はキャンセル済みで、新しい文だけが再生された。新しい文の開始は690 ms。再生中の Esc とウィンドウ終了も通過した。
- 話者・スタイル、話速1.25、音量125%、高さ0.05、抑揚0.8、間1.3が合成要求に適用され、再起動後に復元された。本文欄は空で、保存したJSONのキーは音声設定だけだった。
- 拡張のページ内アイコン、ブラウザへの再注入、タブごとの停止はブラウザ固有の操作。Windows版の入力は本文欄で、停止は要求とウィンドウの寿命に紐づけた。他アプリの選択文字、グローバルショートカット、画面範囲OCRは後続候補とする。

物理スピーカー・イヤホンでの聴感は未確認。「概要」＋上記の長文を再生し、文境界の音切れと、Escで停止して別の短文を開始した際の音の重なりを聴く。支援技術について自動確認したのはフォーカスと通知イベントまで。

## 0.1.0 の初回検証（2026-11-25）

Windows 11 Pro x64、AMD Ryzen 5 3600、VOICEVOX Engine 0.25.2。話者はずんだもん・ノーマル（スタイル 3）、話速 1.0、音量 100%。Electron 45.5.0 を同梱した Windows 版 0.1.0 の ZIP を展開し、開発サーバーを使わずに EXE を起動した。引数なしの通常起動でも「VOICEVOX リーダー」ウィンドウが開き、閉じてプロセスが終了した。

## 実エンジンと配布画面での計測

本文欄に入力し、Ctrl+Enter の Enter キーイベントから最初の HTMLAudioElement の `playing` イベントまでを計測した。「途中の合成待ち」は、前の音声の `ended` 時に次の音声がなく、再生の再開に必要な蓄積を待った時間の合計。「再生イベントの間隔」は、前の `ended` から次の `playing` までの実測で、メディア要素の切り替え時間も含む。各入力について同一走行での値をミリ秒に丸めて記録した。

| 入力 | 単位数 | 最初の再生まで | 途中の合成待ち | 再生イベントの間隔（順に） |
|---|---:|---:|---:|---|
| 「こんにちは。」 | 1 | 477 ms | 対象なし | 対象なし |
| 「朝の便り」「窓を開けました。」「公園の桜が咲いています。」を改行で連結 | 3 | 480 ms | 0 ms | 16、13 ms |
| 「朝の川沿いの道を歩きながら鳥の声を聞きました」を区切らず 7 回反復 | 2 | 3,124 ms | 0 ms | 15 ms |
| 「概要」の後で改行し、上記の長文を追加 | 3 | 3,544 ms | 0 ms | 20、16 ms |
| 長文の合成中に停止し、直後に「こちらは次の文章です。」を開始 | 1 | 3,707 ms | 対象なし | 対象なし |

各本文について、配布画面の分割結果・エンジンが受け取る合成単位・各単位の再生開始と終了の順序を突き合わせ、重複・欠落がないことを確認した。短い見出しの後に長い合成が続く条件では、初回再生の前に待ち時間が発生した。今回の複数単位の入力では再生途中の合成待ちは観測されなかった。エンジン内部の休止やスピーカーから実際に聞こえる時間は計測対象外。

## 停止・復旧・配布範囲

- 実エンジンへの `/synthesis` 要求開始後、準備中に Esc で停止し、別文章を開始できた。再生中の Esc と再生中のウィンドウ終了も確認した。停止の効力はリーダー側での通信中断と再生・表示の破棄までで、別プロセスのエンジン内部が直ちに空くことは前提にしない。
- テスト専用の空きポートに接続して実際の接続拒否を発生させ、未起動の案内を確認した。そのポートに同じ VOICEVOX の別プロセスを起動し、同じ画面の「再接続」で本文を保持して再生できた。通常の計測先は `127.0.0.1:50021`。既存エンジンに終了・再起動操作は行っていない。
- 話者・スタイルを切り替え、話速 1.25、音量 65% へ変更し、再生中に終了した。再起動後の画面で全項目の復元と本文欄が空であることを確認した。
- 停止後に旧要求の成功・失敗・再生イベントを意図的に遅着させる単体テスト、先読み上限、音声 URL の解放、合成失敗後の再開を検査した。拡張の文章整形・バッファリング・先読み・再生・キュー・合成失敗回帰、JavaScript 構文検査、静的セキュリティ監査も実行した。
- Chrome 配布 ZIP は従来の `tools/pack.ps1` で生成し、全 51 エントリに Windows 用ファイルがないことを確認した。Windows 版のビルドと再現手順は [Windows 版 README](../desktop/README.md) を参照。

## 手元での聴感確認

Windows の普段使う出力デバイスで、表の「概要」＋長文を読み上げ、見出しから本文への間と境界の音切れを聴く。続いて再生中に Esc を押し、別の短文を Ctrl+Enter で開始して、前の音声が混ざらないことを聴く。自動確認したのは再生イベントと状態遷移までで、実際の聞こえ方は未確認。
